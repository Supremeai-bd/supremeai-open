# রিট্রাই হ্যান্ডলার ডকুমেন্টেশন (Retry Handler Documentation)

## ওভারভিউ

রিট্রাই হ্যান্ডলার হল একটি পাওয়ারফুল ডেকোরেটর যা অস্থায়ী ব্যর্থতা থেকে সুষ্ঠুভাবে রিকভার করতে সাহায্য করে। এটি এক্সপোনেনশিয়াল ব্যাকঅফ, জিটার, এবং রিট্রাই বাজেট ম্যানেজমেন্ট সাপোর্ট করে।

## বৈশিষ্ট্যসমূহ

- **এক্সপোনেনশিয়াল ব্যাকঅফ**: প্রতিটি ব্যর্থ চেষ্টার পর বিলম্ব বৃদ্ধি পায়
- **জিটার**: থান্ডারিং হার্ড প্রতিরোধে সাহায্য করে
- **কাস্টম এক্সেপশন ফিল্টারিং**: শুধুমাত্র নির্দিষ্ট এক্সেপশনের জন্য রিট্রাই করে
- **কলব্যাক সাপোর্ট**: রিট্রাই এবং সর্বাধিক রিট্রাই পরিস্থিতির জন্য কলব্যাক
- **রিট্রাই বাজেট**: সিস্টেম ওভারলোড প্রতিরোধে টোকেন বাকেট ব্যবহার করে

## ব্যবহার

### বেসিক ব্যবহার

```python
from backend.core.retry_handler import retry_handler


@retry_handler(max_retries=3, delay=1.0, backoff=2.0)
async def my_async_function():
    # আপনার অ্যাসিঙ্ক কোড এখানে
    pass


@retry_handler(max_retries=3, delay=1.0, backoff=2.0)
def my_sync_function():
    # আপনার সিঙ্ক কোড এখানে
    pass
```

### কলব্যাক সহ ব্যবহার

```python
def on_retry_callback(attempt: int, exception: Exception):
    print(f"চেষ্টা #{attempt} ব্যর্থ হয়েছে - {exception}")


def on_max_retries_callback(exception: Exception):
    print(f"সর্বাধিক রিট্রাই সম্পন্ন - চূড়ান্ত এক্সেপশন: {exception}")


@retry_handler(
    max_retries=3,
    delay=1.0,
    backoff=2.0,
    on_retry_callback=on_retry_callback,
    on_max_retries_callback=on_max_retries_callback,
)
async def my_function():
    # কোড এখানে
    pass
```

### রিট্রাই বাজেট সহ ব্যবহার

```python
from backend.core.retry_handler import retry_with_budget


@retry_with_budget(max_retries=2, delay=0.3, backoff=1.5)
async def my_budgeted_function():
    # কোড এখানে
    pass
```

## প্যারামিটার

- `max_retries`: সর্বাধিক রিট্রাই চেষ্টার সংখ্যা (ডিফল্ট: 3)
- `delay`: প্রাথমিক বিলম্বের সময় সেকেন্ডে (ডিফল্ট: 1.0)
- `backoff`: ব্যাকঅফ গুণক (প্রতিটি রিট্রাইতে বিলম্ব বৃদ্ধি হয়) (ডিফল্ট: 2.0)
- `exceptions`: রিট্রাইয়ের জন্য ধরন (শুধুমাত্র এই ধরনের এক্সেপশনগুলির জন্য রিট্রাই হবে) (ডিফল্ট: (Exception,))
- `use_jitter`: জিটার ব্যবহার করবে কিনা (থান্ডারিং হার্ড প্রতিরোধে সাহায্য করে) (ডিফল্ট: True)
- `on_retry_callback`: প্রতিটি রিট্রাই পরে কল হবে এমন ফাংশন (বৈকল্পিক)
- `on_max_retries_callback`: সর্বাধিক রিট্রাই শেষে কল হবে এমন ফাংশন (বৈকল্পিক)

## সুবিধাসমূহ

1. **অটোমেটিক এসিঙ্ক/সিঙ্ক ডিটেকশন**: ডেকোরেটর নিজে থেকে বুঝতে পারে যে ফাংশনটি এসিঙ্ক নাকি সিঙ্ক
2. **থান্ডারিং হার্ড প্রতিরোধ**: জিটার এবং এক্সপোনেনশিয়াল ব্যাকঅফ সহ সুষ্ঠু রিট্রাই
3. **বাংলা লোকালাইজেশন**: সম্পূর্ণ বাংলা কমেন্ট এবং লগ মেসেজ সহ
4. **রিসিলিয়েন্ট ডিজাইন**: অস্থায়ী ব্যর্থতা থেকে সুষ্ঠুভাবে রিকভার করে

## ব্যবহারের ক্ষেত্র

- এপিআই কল যেগুলো অস্থায়ী কারণে ব্যর্থ হতে পারে
- ডাটাবেস কানেকশন রিট্রাই
- ফাইল অপারেশন যেগুলো কনকারেন্ট অ্যাক্সেসের কারণে ব্যর্থ হতে পারে
- নেটওয়ার্ক অপারেশন
- থার্ড-পার্টি সার্ভিস কল

## সাবধানতা

- রিট্রাই হ্যান্ডলার শুধুমাত্র ইডেমপোটেন্ট অপারেশনের জন্য ব্যবহার করুন
- সর্বাধিক রিট্রাই এবং বিলম্ব সময় যাচাই করুন যাতে সার্ভিস রিসপন্স টাইম খারাপ না হয়
- কাস্টম এক্সেপশন টাইপ ব্যবহার করুন যাতে শুধুমাত্র রিট্রাইয়ের উপযোগী এক্সেপশনগুলোই রিট্রাই হয়
