# Content (Card 4 Status and assets / Card 7 stickers and greetings)

Shared by both cards: production uses native content tools, the publish step optionally uses My Browser or Computer Use on a verified official surface, and nothing is published without user confirmation.

## Card 4: Status posts and promotional assets

**Trigger phrases**: "make a WhatsApp Status video", "an Independence Day poster to post as my Status", "a promo image for my shop"
**Input contract**: subject plus spec (Status = 9:16 vertical; profile photo = 1:1) plus brand elements (logo, palette; optional).
**Steps**: 1) Generate the video or poster to the agreed spec. 2) Deliver a preview. 3) User confirms content, account product, and audience. 4) Detect whether Status publishing is available on that exact account and Web/Desktop surface. Personal WhatsApp guidance currently covers Web, Mac, and Windows; WhatsApp Business linked-device guidance currently lists Status add/delete as unsupported. 5) Optionally publish through My Browser or Computer Use only on the verified account-appropriate surface, with final confirmation immediately before publishing; otherwise hand over the file.
↯ Generation quota is exhausted → downgrade to a static image plus a note describing the intended motion, and say so plainly.
**Output assertions**: the spec is correct (9:16 or 1:1); if publishing was executed, the Status is visible.
**Recordability**: not a default reusable recording. The publish step is short, consequential, audience-sensitive, and product-surface-dependent. Use an O1 observation to qualify the route; record a reusable flow only if a stable account-specific mainline and rollback are proven separately.

## Card 7: Stickers and holiday greetings

**Trigger phrases**: "make me a sticker set", "make a birthday card"
**Input contract**: style, subject, and copy points; for stickers, state the goal (personal forwarding or a sticker pack).
**Steps**: 1) Generate a set of 4-8. 2) Deliver the image pack plus current import guidance. 3) If the user asks to send the pack to "Message yourself," treat that as a normal send and confirm it at the final boundary.
**Output assertions**: transparent background, dimensions and file type accepted by the current official import flow, and no typos in the copy. If current import requirements are not verified, deliver the source assets and guidance without claiming pack-ready status.
