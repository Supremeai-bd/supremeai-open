# Telegram Route Contract

## Status first

Assign exactly one status per workflow:

- EXECUTABLE: deterministic file/content work with a fixture and oracle.
- CONDITIONAL-O1: a selected Web/Desktop client action whose exact path and recovery have not yet passed a disposable-account live test.
- GUIDANCE: supported product/API concept without a verified Manus runtime or current surface procedure.
- REFUSE: unsolicited DMs, fake engagement, secret capture, security bypass, or other prohibited/unsafe intent.

## Route precedence

1. Identify human account, bot, or no Telegram identity.
2. Name the durable state: supplied/exported files, composer draft, published message, scheduled item, device/session state, sticker pack, or bot integration.
3. Preserve an explicit Web/Desktop choice; prove each surface independently.
4. Verify current runtime, account fixture, authority, secret path, scope, cursor, consequence, and recovery.
5. Choose the least fragile route and state its status before acting.

## Truth boundaries

- Prepared copy is not an in-app draft.
- Composer text is not a sent message.
- A scheduled form is not a queue item or future delivery.
- A documented Bot API is not a Manus integration.
- Prepared sticker assets are not a published pack.
- A selected export is not all account history.
- My Browser is not Computer Use.
