# Telegram Verification Manifest

Record route status, identity, selected surface/build, named scope, source cursor, exact target, consequence type, fixture, recovery point, completed/skipped/failed counts, and secret exclusions.

## File/export work

- source archive hashes and authorized data path;
- detected schema and scope;
- Telegram completion-summary reconciliation when available;
- chat/message/media counts, unsupported types, and parse exceptions;
- unchanged source files and output index location.

## Web/Desktop state

- disposable account and selected surface O1;
- exact target and visible start/end state;
- zero writes for read-only work;
- draft/send/schedule/pin/session states verified separately;
- ambiguous state queried before retry.

## Bot runtime

- actual runtime name/version and bot identity;
- permissions, opt-in basis, secure token surface, revoke path, and denied-permission test;
- input update ID separated from output dedupe;
- destination, payload hash, resulting message ID, timeout reconciliation, and no secret in artifacts.

Never infer state or completeness from a click, request success, or product documentation alone.
