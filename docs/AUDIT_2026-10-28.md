## 1. Executive summary

Two systemic frictions reproduce on pristine main. **F1** is a repository-hygiene wedge:
exactly one tracked file is committed with CRLF line endings while `.gitattributes`
mandates `* text=auto eol=lf` / `*.ts text eol=lf`. Every fresh clone of main therefore
shows a permanent 164/164-line phantom diff on that file, and — because `git rebase`
refuses to run with unstaged changes — the loop's own pre-work and pre-push rebase
guards (`pre_work_rebase_guard`, `pre_push_rebase_guard`, Invariant #1) fail closed for
**every agent on every machine** unless they know the `update-index --assume-unchanged`
workaround. This auditor hit the wedge on a clean clone and reproduced all symptoms.
**F2** is board-state drift: of the 15 open work orders visible through the Tower's
`bridge_work_queue`, three (`#1530`, `#1552`, `#1565`) describe defects that no longer
reproduce on live main — later landed PRs (#1539/#1541 lineage, #1578, #1580, #1582,
#1583) already fixed them. Under U3 ("resolved incidents are skipped with evidence,
never re-solved") these are stale orders; a solver acting on them today would waste the
work budget or, worse, attempt to "fix" code that is already correct.

Both items carry the smallest safe remediation: F1 is fixed in this patch by a
single-file LF renormalization (zero content change), F2 is discharged by the evidence
tables in §3 so maintainers can label and close the three orders. CI-gate proposals in
§5 would have caught both classes before they reached the board.

## 2. Findings

### F1 (P0, FIXED in this patch) — CRLF blob wedges Dual-Rebase for every agent

- **Evidence:**
  - `git ls-files --eol infrastructure/mcp-control-plane/src/tools/tenant.tools.ts`
    → `i/-text w/-text attr/text eol=lf`: the committed blob contains 164 CRLF pairs
    plus 1 trailing lone CR (165 CR bytes total) and no final newline, while
    `.gitattributes` line 2 (`* text=auto eol=lf`) and line 10 (`*.ts text eol=lf`)
    declare the path text/LF. `git hash-object` proves the phantom: hashing the
    worktree file **with** the clean filter yields the LF-normalized blob (≠ HEAD
    blob `7f576d9e`), so git considers the checkout permanently dirty.
  - `git status` on a fresh clone reports the file modified with a 164-insertion /
    164-deletion diff that is pure EOL churn (`git diff --ignore-cr-at-eol --stat`
    is empty — zero content delta).
  - The phantom regenerates faster than `git -c rebase.autoStash=true rebase` can
    suppress it (stash → rebase still refuses → stash pop conflicts). Only
    `git update-index --assume-unchanged <path>` unblocks the rebase.
  - Repo-wide CR scan `git grep -Il $'\r' -- .` returns exactly this one file — it is
    the sole offender and the sole poison source.
- **Impact:** Invariant #1 (Dual-Rebase at work-start AND pre-push, "0 behind") is
  unexecutable as written on any clone of main. The loop's fail-closed rebase guards
  turn a hygiene defect into a dispatch outage for the whole agent fleet.
- **Remediation (this patch):** commit the LF-normalized blob of the single file
  (164 CRLF → LF, trailing lone CR → final newline; blob replaces 165 CR bytes with
  LF endings). Zero content change: byte-identical after CR-stripping and
  trailing-newline normalization; TypeScript output is unaffected. After the patch
  lands, fresh clones are clean, both rebase guards execute as designed, and the
  proposed G1 gate (`git grep -Il $'\r'` = empty) passes repo-wide.

## 5. CI gate proposals (patches for maintainer application)

### G1 — `.gitattributes` conformance guard (prevents the entire F1 class)

Fail CI when any tracked text file still carries CR bytes. One step in the existing
`fast-lint-syntax-preflight` job (add after checkout):

```yaml
      - name: gitattributes EOL conformance guard (no CR bytes in tracked text)
        run: |
          if git grep -Il $'\r' -- . | grep -v '^\.gitattributes$'; then
            echo "::error::CRLF-committed files detected (violates .gitattributes eol=lf);"
            echo "::error::run: git add --renormalize . && git commit -m 'chore(hygiene): renormalize EOL'"
            exit 1
          fi
```

Cheap (single grep), dependency-free, and it converts the silent per-clone wedge into
a loud merge-time failure. Note `--renormalize` only helps when the attributes file is
already in force, so the guard belongs in the same job that already enforces lint
parity.

### G2 — stale-work-order evidence sweep (automates U3 for `bridge:queued`)

Scheduled cadence role (fits the existing auditor slot, 24h): for each
`bridge:queued` order, re-run its defect claims against a fresh `origin/main`
(reproduction scripts or claim-specific probes like §3); when no claim reproduces,
post the evidence table as an issue comment and apply `state:stale-evidence`
(new label, added to the loop's `EXCLUDED_LABELS` in the same PR). Effect: the board
only ever advertises incidents that are true on live main, and the loop's
`pick_next_issue()` stops surfacing dead orders automatically once the label exists.

## 6. Reflection Evidence

- **why:** the CRLF wedge (F1) was hit and reproduced by this agent on a pristine
  clone during its assigned cadence cycle — the rebase invariant that the whole
  federation depends on fail-closes on main today; a one-file renormalization is the
  smallest superior replacement (delete the poison blob rather than teaching every
  agent a workaround). The stale-order evidence (F2) is filed because U3 explicitly
  requires evidence-backed skipping, and 3/15 of the board being stale is a
  measurable tax on every future dispatch cycle.
- **alternatives_rejected:**
  1. *Fix by adding `.gitattributes` exception (`*.ts -text`)* — rejected: it would
     bless the CRLF blob and contradict the repo's own byte-parity goal stated in
     `.gitattributes` line 1.
  2. *Document the `assume-unchanged` workaround in CONTRIBUTING instead of fixing
     the blob* — rejected: docs don't stop `git rebase` from refusing; every fresh
     clone (including CI runners using `persist-credentials`-style checkouts) keeps
     hitting the wedge.
  3. *Renormalize the whole repo in one commit* — rejected: `git grep -Il $'\r'`
     shows exactly one offending file; a repo-wide commit would inflate the slice
     beyond need (cohesive-sizing invariant) and touch files with no defect.
  4. *Self-land G1/G2 into `pipeline.yml` / loop labels* — rejected: `.github/` is a
     protected path (WO #1554 precedent); gates are proposed as exact patches for
     maintainer application instead.
  5. *Close the three stale WOs directly via Tower tools* — rejected: labeling/closing
     other parties' work orders is an admin action; this audit files the evidence and
     leaves the board decision to maintainers.
