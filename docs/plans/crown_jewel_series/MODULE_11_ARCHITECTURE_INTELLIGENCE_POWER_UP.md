# Module 11 — Architecture Intelligence Power-Up

## বাংলা সারসংক্ষেপ

এই প্ল্যাটফর্মে ১৯৪টি মডিউল আছে, আর তাদের ওয়্যারিং-সত্য আজও **রানটাইম-অডিট চালিত** — `scripts/sync_modules_list.py` চালিয়ে `docs/audit_reports/module_wiring_audit.json` থেকে `MODULES_LIST.md` জেনারেট হয় (১২৬ operational, ৬১ dormant, ৩ environment-dependent, ১ broken)। কিন্তু **কোড-স্তরের স্ট্যাটিক ডিপেন্ডেন্সি-গ্রাফ নেই**: কোনো ফাইল/মডিউল কাকে আমদানি করে, কোন সাইকেল তৈরি হয়েছে, কোন বাউন্ডারি ভাঙা — এসব প্রশ্নের উত্তর আজ কেবল ad-hoc grep। ফলে প্রতিটি বড় রিফ্যাক্টর (যেমন ERR-F02 মেমোরি-কনসলিডেশন) **অন্ধ-রিফ্যাক্টর** হয়ে ওঠে — প্রভাব-বিস্তার (blast-radius) সংখ্যায় না জেনে হাত দিতে হয়।

এই নীলনকশা প্ল্যাটফর্মের মূল-দর্শনের পক্ষেই দাঁড়ায়: **zero cost** (pydeps/dependency-cruiser — উভয়ই ফ্রি OSS, কোনো পেইড সার্ভিস নয়), **lightweight** (devDependencies-কেবল — রানটাইম-বাজেটে শূন্য-এন্ট্রি, 512MB free-tier boot অস্পৃশ্য), **fast smooth** (গ্রাফ CI/নাইটলি-তে; প্রোডাকশন hot-path-এ শূন্য-স্পর্শ; baseline-N নীতিতে লেগেসি-ঋণ কখনো PR-ব্লকার নয়), **zero hardcode** (রুল/থ্রেশহোল্ড/বেসলাইন সব ডেটা-ফাইল বা config — কোডে ম্যাজিক-সংখ্যা নেই)।

**সততা-দাবি:** এটি `proposed` বিশ্লেষণ-স্তরের নীলনকশা — নিজে থেকে executable নয় (Gate 2 ফাউন্ডার-অনুমোদন বাধ্যতামূলক); CI-workflow ফাইল সৃষ্টি এখানে *প্রস্তাবিত*, *সম্পাদিত* নয়।

## Part 2 — Six-Field Analysis

### ২.১ কী আছে (What exists — file:line evidence)

1. **রানটাইম-ওয়্যারিং-সত্য:** `MODULES_LIST.md` (১৯৪-মডিউল টেবিল) ← `scripts/sync_modules_list.py` ← `docs/audit_reports/module_wiring_audit.json`; প্রতি মডিউলে caller-evidence + test-evidence কলাম।
2. **শাসন-স্ক্রিপ্ট সংস্কৃতি:** `scripts/governance/lint_plans.py` — ডকুমেন্ট-শাসনে error/warning মডেল প্রমাণিত।
3. **CI-অবকাঠামো:** `.github/workflows/`-এ ১৯টি workflow (ci.yml, ci-advanced-checks.yml, constitution-governance.yml, scheduled-deep-audit.yml, qa-contract.yml, dast-zap.yml, db-retention.yml ইত্যাদি) — গ্রাফ-ওয়ার্কফ্লোর হোস্টিং-জায়গা প্রস্তুত।
4. **অভিজ্ঞতা-মতবাদ:** Module 10-এর knip zero-false-positive-বেসলাইন মতবাদ + Module 09-এর dormant-শ্রেণিবিন্যাস — CI-গেটিং-এর আগে বেসলাইন, এই সিরিজেই প্রমাণিত।

### ২.২ কী নেই (What's missing)

1. কোনো **স্ট্যাটিক ডিপেন্ডেন্সি-গ্রাফ** নেই — backend (pydeps) ও frontend (dependency-cruiser) দুটোতেই শূন্য (৩-manifest rg-প্রমাণ, base ed35eaf)।
2. কোনো **rules-ডেটা-ফাইল** নেই — `architecture-rules.yml` অনুপস্থিত; cycle/boundary/layering রুল কোথাও ফাইলাইজড নয়।
3. কোনো **baseline-N নীতি** নেই — বর্তমান লঙ্ঘন-সংখ্যা কোথাও রেকর্ডেড নয়; ফলে নতুন-লঙ্ঘন পুরোনো-লঙ্ঘনের সাথে মিশে অদৃশ্য।
4. কোনো **PR-লেভেল blast-radius** ফিডব্যাক নেই — merge-পূর্বে কোনো reviewer জানে না এক changed-edge কতগুলো মডিউল নাড়ায়।
5. **স্ট্যাটিক-বনাম-রানটাইম অমিল** কোথাও যন্ত্রগতভাবে তুলনা করা হয় না (গ্রাফ বলে কলার-আছে, অডিট বলে dormant — এই দ্বন্দ্ব ধরা পড়ে না)।

### ২.৩ কী করতে হবে (What to do)

- **P-A — স্ট্যাটিক গ্রাফ জেনারেশন:** backend-এ `pydeps`, frontend-এ `dependency-cruiser` — **devDependencies-কেবল**; আউটপুট JSON (মানুষ-পাঠযোগ্য ছবি optional); রানটাইমে কোনো প্যাকেজ যোগ নয়।
- **P-B — রুল-ডেটা-ফাইল:** `architecture-rules.yml` — cycle-নিষেধ, boundary (যেমন `backend/tools/*` → `backend/api/*` নয় — প্রস্তাবিত প্রারম্ভিক সেট কেবল, ফাইনাল ফাউন্ডার-রিভিউয়ে), layering রুল; রুল কোডে নয়, ফাইলে (zero-hardcode)।
- **P-C — baseline-N:** প্রথম চালনায় বর্তমান লঙ্ঘন-সংখ্যা N রেকর্ড (`docs/audits/`-এ ডেটেড baseline-ডকুমেন্ট + সংখ্যা env/config-চালিত রেফারেন্স); পরবর্তী প্রতি চালনায় `≤ N → pass`, `> N → fail` — N-হ্রাস একমুখী ratchet।
- **P-D — রিপোর্ট-স্ক্রিপ্ট:** `scripts/governance/architecture_check.py`-জাতীয় স্ক্রিপ্ট — lint_plans.py-প্রেসিডেন্টে; আউটপুট: লঙ্ঘন-তালিকা + প্রতি-PR changed-edge blast-radius।
- **P-E — workflow প্রস্তাব (ফাউন্ডার-গেটেড):** `architecture-pr.yml` (PR diff-মন্তব্য) + `architecture-nightly.yml` (পূর্ণ পুনর্নির্মাণ + drift + orphan) — **কেবল ফাউন্ডার Gate 2 অনুমোদন ও zero-false-positive বেসলাইন-রেকর্ডের পরে**; এই নীলনকশা নিজে কোনো workflow-ফাইল সৃষ্টি করে না।
- **P-F — স্ট্যাটিক-রানটাইম মার্জ:** গ্রাফ-কলার-সেট বনাম `module_wiring_audit.json`-caller-সেট — অমিল-রিপোর্ট (কোডে আমদানি আছে কিন্তু অডিট বলে dormant, বা বিপরীত)।
- **P-G — AGENTS.md Rule 3 ও Rule 5 এনফোর্সমেন্ট (ক্রস-সার্কেল কাপলিং ও জিরো-বাইপাস অডিট):**
  - **Rule 5 (Federated Decoupling):** সার্কেলগুলো নিজস্ব ডোমেইন শাসন করবে এবং সেন্ট্রাল কন্ট্রোল টাওয়ার অর্কেস্ট্রেশন চালাবে। কোনো ওয়ার্কার মডিউল/সার্কেল সরাসরি অন্য ওয়ার্কারের সাথে যুক্ত হবে না (যেমন Memory ও Trio সরাসরি সংযুক্ত নয়)।
  - **Zero-Bypass Inference Boundary AST-চেক:** `backend/services/llm_gateway.py` ব্যতীত রিপোজিটরির কোনো এজেন্ট বা টুলে সরাসরি `litellm`, `openai`, বা র `httpx` মডেল কল করা নিষিদ্ধ। `architecture_check.py` স্ট্যাটিকভাবে এই বাউন্ডারি লঙ্ঘন আটকে দেবে।

### ২.৪ কীভাবে করব (How — phase-ordered, flag-gated)

1. **Phase 1 (বেসলাইন):** দুই devDependency + গ্রাফ-জেনারেশন-স্ক্রিপ্ট; সময়-বাজেট মাপা (pydeps-এর বড়-রিপো ধীরগতি-ঝুঁকির ক্বান্টিফায়েড সংখ্যা এখানেই বের হবে); CI-স্পর্শ **শূন্য**।
2. **Phase 2 (রুল+বেসলাইন):** `architecture-rules.yml` প্রারম্ভিক-সেট (ক্রস-সার্কেল ডিরেক্ট ইমপোর্ট ও জিরো-বাইপাস রুল অন্তর্ভুক্ত) + baseline N রেকর্ড; N-এর মান ফাউন্ডার-অনুমোদিত; সব থ্রেশহোল্ড config/env-চালিত।
3. **Phase 3 (রিপোর্ট):** `architecture_check.py` — কেবল স্থানীয়/চাহিদামাফিক চালনা; কোনো গেট নয়, কেবল দৃশ্যমানতা।
4. **Phase 4 (CI — ফাউন্ডার-গেটেড):** zero-false-positive প্রমাণিত হলে তবেই workflow-ফাইল; প্রথম মাস warn-only (Module 10 knip মতবাদ); baseline-N fail-মোড তার পরে।
5. প্রতিটি ধাপে flag/kill-switch (config-চালিত); কোনো ধাপই API/boot/hot-path স্পর্শ করে না।

### ২.৫ বেনিফিট (Benefit)

1. **অন্ধ-রিফ্যাক্টর শেষ:** ERR-F02-জাতীয় কনসলিডেশনে blast-radius সংখ্যায় জানা যাবে merge-এর আগেই।
2. **সাইকেল ও ক্রস-সার্কেল কাপলিং প্রতিরোধ:** circular import ও নিষিদ্ধ ক্রস-সার্কেল সরাসরি ডিপেন্ডেন্সি নতুন করে জন্মানোর আগেই ধরা পড়বে।
3. **জিরো-বাইপাস স্থাপত্য সুরক্ষা:** কোনো ডেভেলপার বা এজেন্ট গেটওয়ে এড়িয়ে সরাসরি মডেল কল করে টোকেন বাজেট বা অডিট ট্রেইল ফাঁকি দিতে পারবে না।
4. **অনাথ-ভবিষ্যদ্বাণী:** স্ট্যাটিক-রানটাইম অমিল Module 09/10-জাতীয় dormant-সমস্যাকে জন্মের সময়েই ধরবে — পরে ৬০-অনাথ গোনার ব্যয় নয়।
5. **শূন্য-মার্জিনাল-ব্যয়:** devDeps + স্ক্রিপ্ট — রানটাইম-বাজেটে শূন্য-এন্ট্রি, ব্যবহারকারী-অভিজ্ঞতায় শূন্য-পরিবর্তন।

### ২.৬ ক্ষতি/ঝুঁকি (Cost/Risk)

1. **বৃদ্ধি-জটিলতা:** আরেকটি স্ক্রিপ্ট+রুল-ফাইল রক্ষণাবেক্ষণ-দায় — প্রশমন: রুল-সেট ছোট শুরু (কেবল cycle + ২-৩ boundary), বৃদ্ধি ফাউন্ডার-অনুমোদনে।
2. **false-positive CI-ক্ষতি:** যদি অপরিপক্ব অবস্থায় গেট চালু হয়, PR-ব্লকার হয়ে CI-বিশ্বাস ভাঙবে (প্রতিষ্ঠাতার পর্যবেক্ষিত ব্যর্থতা-প্যাটার্ন) — প্রশমন: warn-only-প্রথম + zero-false-positive-প্রমাণ-পূর্বশর্ত (কঠোর)।
3. **pydeps-গতি:** বড় গ্রাফে ধীর — প্রশমন: Phase 1-এই মাপা baseline; ধীর হলে স্কোপ (শুধু `backend/core` + `backend/services`) — সিদ্ধান্ত পরিমাপের পরে, অনুমানে নয়।
4. **নতুন-নির্ভরতা:** devDependency-ও সরবরাহ-শৃঙ্খল — প্রশমন: উভয় টুল প্রতিষ্ঠিত OSS (BSD/MIT); lockfile-বাঁধা; রানটাইমে শূন্য-উপস্থিতি।

## Part 5 — Verification & Rollback (Gates 4–6)

- **Gate 4 (প্রমাণ):** Phase 1-এর গ্রাফ দুইবার-চালনায় ডেল্টা-শূন্য (reproducibility); rules-parser positive+negative fixture; baseline-N দুই-মুখ সেমান্টিকস-টেস্ট।
