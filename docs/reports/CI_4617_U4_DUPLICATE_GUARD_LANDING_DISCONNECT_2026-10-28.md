## 3. Guard anatomy (pipeline.yml, `duplicate-pr-guard`, L305–367)

The job is gated `if: github.event_name == 'pull_request'` (L307). Its detection logic, verbatim semantics:

1. **Escape hatch**: `guard-exempt` label skips the job.
2. **Own targets**: `TARGET_ISSUES` = explicit `Closes|Fixes|Resolves #N` matches in the PR's own title/body; `BRANCH_ISSUES` = `issue-N` tokens in the branch name; fallback to any `#N` reference if both are empty.
3. **Competitor scan**: `gh pr list --state open --json number,title,body,headRefName` — a **live snapshot** of every other open PR at execution time.
4. **Match rule** per target issue `#N`: competitor's title/body contains `closes|fixes|resolves #N` (whole-token, the #120 fix) **OR** competitor's branch name contains digit token `N` with non-digit boundaries. First match wins; `exit 1`.

Two properties matter for this finding: the match surface includes **plain closing references in other PRs' bodies** (semantic-free — it cannot distinguish a true fixer from a lane-bookkeeping closer), and the whole check is a **point-in-time snapshot** (the verdict is only as fresh as the listing).

## 4. Auto-landing anatomy — the disconnect (pipeline.yml, `auto-landing`, L794–806)

```yaml
auto-landing:
  name: "🛬 Autonomous Auto-Landing"
  needs: [branch-naming-guard, claim-guard, boundary_sanitization_guard,
          test-matrix, secrets-scan, mcp-tower, studio-verification]
  if: |
    always() &&
    github.event_name == 'pull_request' &&
    github.event.pull_request.draft == false &&
    !contains(needs.*.result, 'failure') &&
    !contains(needs.*.result, 'cancelled')
  concurrency:
    group: landing-merge-open
    cancel-in-progress: false
```

- **`duplicate-pr-guard` is not in `needs`.** The landing gate evaluates exactly seven jobs; a `failure` result from the duplicate guard never appears in `needs.*.result`, so `!contains(..., 'failure')` stays true and the merge proceeds. In run 4617 the landing job did not merely "tolerate" the guard failure — it executed the squash-merge inside the same failing run.
- **Event-surface asymmetry (secondary hole)**: the landing job itself only runs on `pull_request` events, but the pipeline also triggers on `push` events for bridge branches (L105 gate). A push-event run of the same sha is guard-free **and** lander-free — harmless by itself, but it means every PR lane normally produces two parallel verdict planes for one commit: a guard-bearing PR-event run and a guard-free push-event run (see the concurrency analysis below). Any consumer of "green per sha" that does not distinguish the planes inherits the asymmetry.
- **Concurrency groups guarantee the parallel planes** (L64–66): `group: ci-open-${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}` with `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`. A push run groups by `github.ref`, a PR run groups by PR number — **disjoint groups**, so a branch push and its PR event never cancel each other and the same head sha runs twice, concurrently, by construction. That is the race window builder; run pair 4616/4617 (3 s apart) is it live.
- **Contrast with the claim gate**: `claim-guard` IS in `needs` — the atomic-claim invariant (U5-family) gates the merge, the anti-duplicate invariant (U4) does not. The asymmetry looks like an oversight rather than a design choice, which is exactly why it is worth a receipt.

- **Refined guard model (source + live A/B)**: (1) targets = explicit closing statements in own title/body ∪ issue-N branch tokens; (2) if both are empty — which is guaranteed for every Refs-wired PR, i.e. the bridge's default for report lanes against still-open findings — the extraction **falls back to all `#N` references in the body**; (3) each target is then matched against other open PRs via closing-verb adjacency OR branch digit-token; (4) failure does not block landing (§4). - **Refined agent-side defense (evidence-bearing, Refs-wired lanes)**: quoting hygiene is necessary but insufficient; the binding rule is **no bare `#N` token in the PR body may name anything an open competitor targets**. In practice: refer to competitor PRs and WOs as "the vehicle PR for the browser lane" or by run ids ("run 4654" — un-prefixed numbers are invisible to the `#[0-9]+` extraction), keep the verbatim `#N` strings inside files (the guard scans title/body only), and accept that the bridge's own `Refs #<issue> Refs <WO>` tail is safe because no open PR targets those numbers. This correction's own submission (a3) is the positive control: its body contains no `#`-prefixed competitor numbers, so a green guard run on it — against the red runs 4654/4678 — completes the A/B/A' triple (quote-capture red, fallback-only red, fallback-aware green) and pins the model end-to-end. The durable fixes stay admin-side (§7).

## 7. Proposed admin-side hardening (NOT agent-actionable; protected path)

Ordered by leverage:

1. **Wire the guard into the landing gate**: add `duplicate-pr-guard` to `auto-landing`'s `needs`. One line; makes U4 enforcement real (a guard failure then trips `!contains(needs.*.result, 'failure')` and blocks the merge). This is the single change that closes the disconnect observed in run 4617.
2. **Forensic metadata in the guard error**: include the competitor's `state` and `updated_at` (already present in the `gh pr list --json` payload) in the `::error` lines, so the next sighting-vs-ground-truth divergence is self-documenting.
3. **De-collide shared-WO closers**: either require the competitor to match the WO's own lane slug token (the `bridge-YYYYMMDD-slug` join key the landing watchdog already standardizes) instead of body closing refs, or skip competitors whose matching `Closes` sits in a bridge Linked Work Order block of a satellite-vehicle PR. Goal: a fixer PR should never be flagged by its own lane's vehicle.
4. **(Optional) unify the verdict planes**: run the guard on push events too, or make push-event bridge runs reuse the PR run's results. Lower priority — after (1), the guard-free push plane cannot reach the merge path, so it degrades to harmless redundancy.
5. **Stale-ancestor hygiene (from §6d)**: the competitor the guard flags may be an open PR whose shared target issue is already closed — definitionally superseded work (receipts five AND six both tripped against the open r1 ancestor PR #1954 while its shared target #1938 was CLOSED on the issue plane). This composes with the §6c verdict-plane legitimacy rule into a two-axis competitor-legitimacy check: PR-plane open + target-issue closed → stale; PR-plane open + WO verdict rejected/absent → illegitimate. Neither rule alone covers both axes observed.
