## Recommended remediation (for the Core CI / security-maintainer owner — recommendation, not a patch)

Matches the row's acceptance criteria one-for-one:

1. **Policy decision first (HITL)**: decide whether GitHub Advanced Security / code scanning
   is an approved capability for the private core repo (plan + security policy).
2. **If NOT enabled**: make the upload step degrade gracefully instead of failing the job —
   publish the SARIF as a workflow artifact and skip the GitHub upload with a clear warning:
   ```yaml
   - name: Upload SARIF to GitHub code scanning
     if: always()
     continue-on-error: true          # GHAS may be unavailable on private repos
     uses: github/codeql-action/upload-sarif@v3
     with: { sarif_file: results.sarif }
   - name: Publish SARIF as artifact (GHAS-unavailable fallback)
     if: always()
     uses: actions/upload-artifact@v4
     with: { name: sarif-report, path: results.sarif }
   ```
   The upload failure then surfaces as a visible warning, the job goes green, and operators
   review the scan report under the run's **Artifacts** tab (document this location in the
   workflow comment or README).
3. **Keep Core Pytest & Lint on its intended push/PR triggers** — the current run skipped it;
   verify trigger wiring after the SARIF gate lands.
4. **If GHAS IS approved**: enable code scanning for the repo, confirm
   `security-events: write` permission, and re-run — upload should then succeed as-is.
