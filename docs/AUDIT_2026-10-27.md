## 2. Findings

### F1 (P0, FIXED in this patch) — machine path severed: `--task-envelope` emits a stub

- **Evidence:** `main()` emitted `{"task_contract": {"version": 1, "task_type":
  "IMPLEMENT"}}`. Consumer A `core/runner/agent_runner.py` (`load_envelope`,
  task-envelope-v1, §2) requires `envelope_version`, `output_format`,
  `task_id`, `objective`, `submission{pathway,base_branch,pr_title_prefix}`,
  non-empty `scope.touching_files` — all absent. Consumer B
  `scripts/agents/execution_bridge.py` requires top-level key `task_envelope`
  plus `task_id/role/specialist_prompt/scope/submission` — key itself was wrong.
  `agent_runner.py` documents `--issue 334 --task-envelope` but the flag did
  not exist (silently swallowed by `parse_known_args`).
- **Impact:** every automation that follows the documented SSOT
  (`docs/AGENT_LOOP_SPEC.md` §2, `docs/AUTONOMY_LOOP_CONTRACT.md`) fails
  closed. Loop→runner→bridge dispatch chain dead since #1526.
- **Remediation (this patch):** `build_task_envelope()` restores the canonical
  shape (SPEC §2), adds `--issue` / `--allow-adhoc`, banner moved to stderr
  (§4b: JSON-only stdout). Proof: emitted envelope validates against BOTH
  consumers' fail-closed validators (28/28 machine-path checks in test
  evidence).

### F2 (P1, FIXED in this patch) — repo's own suite red on main: stale freshness tests

- **Evidence:** `pytest tests/test_constitution_freshness.py` → 3 failures on
  main `d0e5c8c`: `test_01` expects the deleted-file triple
  (`AGENT_RULES.md`), `test_13` unlinks a file no longer in the surface,
  `test_18` scripts divergence on the deleted file. r2 changed
  `RULE_FRESHNESS_FILES` but not its SSOT-sync tests.
- **Remediation (this patch):** the 3 tests synced to the landed double
  surface. Suite: 100 passed / 0 failed (was 97/3).

### F3 (P1, FIXED in this patch) — dispatch filter drift: solver sent to unclaimable issues

- **Evidence:** `main()` skip set `{status:claimed, status:in-progress,
  anchor-hub, admin-only}` diverged from `pick_next_issue()`'s excluded labels
  (adds `state:seq-hold`, `blocked-by-upstream`, `mirror:private`). CI's own
  contract test asserts `mirror:private` boards must no-op (#122) — main()
  violated it by dispatching solver onto private-mirror and seq-held issues
  that external agents can never claim.
- **Remediation (this patch):** single `BOARD_EXCLUDED_LABELS` frozenset (SSOT,
  union of both sets) consumed by both readers; behavior asserted by tests.

### F4 (P2, FIXED in this patch) — duplicated `CONTRACT_VERSION` line

- **Evidence:** `--verify-only` printed the marker twice (inside `run_verify()`
  and again in `main()`). SPEC §4b requires it as the final stdout line; the
  duplicate was noise that tripped byte-exact consumers.
- **Remediation:** printed exactly once, still the final line (verified).

### F5 (P2, FIXED in this patch) — last bare `subprocess.run` in `main()`

- **Evidence:** after r2's gh-degrade fix, the board read still bypassed
  `run_cmd()` via a raw `subprocess.run` + try/except. `run_cmd()` already
  returns exit 127 for missing binaries with timeout handling.
- **Remediation:** board read via `run_cmd()`; honest
  `gh CLI unavailable (exit N)` degrade retained and tested.

### F6 (P3, accepted risk, flagged for admin) — group-registry divergence

- **Evidence:** code `VALID_GROUPS = {core, gateway, studio, vscode, browser,
  docs, infra, marketplace, federation}` vs `AGENT_LOOP_SPEC.md` §3 registry
  `{agent-orchestration, mcp-tower, core-engine, schemas-contracts,
  infra-ops}` (declared "authoritative group surface"). SPEC-documented group
  `agent-orchestration` raises `ValueError` in `build_task_contract()`.
  Consumers (`agent_runner`, `execution_bridge`) do not validate `group`, so
  the envelope path stays safe, but the SPEC §3 SSOT claim is false today.
- **Recommendation:** admin decision required — either re-align
  `VALID_GROUPS` to SPEC §3 (touches tier-6 guard + defaults) or amend SPEC §3
  to the satellite registry. Not drive-by-fixable (cross-surface contract).

### F7 (P3, accepted, documented) — dead first-choice import in `instruction_builder.py`

- **Evidence:** `scripts/agents/instruction_builder.py::_load_rules` lazily
  imports `continuous_agent_loop._load_agent_rules`, a symbol that exists in
  no revision of the loop (verified via git history) — always falls back to
  `role_registry.constraints`. Graceful, but the stale comment implies a SSOT
  parser that never runs; AGENT_RULES.md is deleted anyway.
- **Recommendation:** drop the dead import block in a future docs/chore slice.

### F8 (P4, observation) — `--verify-only` in CI cannot fail on logic drift

- **Evidence:** the matrix step only proves `--verify-only` exits 0; tier
  honesty is static, not behavioral. The parity guard covers tier literals,
  not envelope/dispatch behavior.

## 3. Proposed CI gates (auditor mandate)

- **G1 — run the suite:** add `pytest tests/ -q` (or the loop-related files)
  to the `test-matrix` job. Would have caught F2 before #1533 landed. Cost:
  seconds, stdlib-only tests, PyYAML already installed.
- **G2 — envelope-surface parity:** extend
  `check_loop_contract_parity.py` with check 7: run
  `continuous_agent_loop.py --task-envelope --allow-adhoc` in a temp env and
  validate output against `execution_bridge.REQUIRED_TASK_KEYS` (stdlib-only,
  no network). Would have caught F1 at the r1/r2 gate.
- **G3 — dispatch-filter parity:** assert
  `main()` and `pick_next_issue()` read the same excluded-label set (e.g. via
  the shared constant — already landed — plus a one-line guard check).
  Would have caught F3.
